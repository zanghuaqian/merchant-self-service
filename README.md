# 商户自助服务助手（一期）· 交互演示工程

按《商户自助服务助手（一期）PRD V1.0》实现的**可点击演示程序**，覆盖「资金未到账」自助诊断全链路，分为两个场景：

| 场景 | 入口 | 说明 |
|---|---|---|
| 盛意旺 App | `app.html` | 复刻 App 首页，底部导航新增「助手」入口，诊断后跳转 App 内功能页修复 |
| 盛意旺公众号 | `wechat.html` | 复刻公众号会话与底部菜单「商户服务 → 自助客服」，含绑定态分流与微信内 H5 修复 |
| 演示导航 | `index.html` | 场景入口、PRD 覆盖点、指标与使用说明 |

## 运行方式

纯静态页面，**双击 `index.html` 即可**，无需构建、无需联网（Bootstrap Icons 走 CDN，离线时仅标注图标不显示，功能不受影响）。

如需本地服务：

```bash
python -m http.server 8099
# 打开 http://localhost:8099/merchant-self-service/index.html
```

## 演示控制台（非产品界面）

每个场景左侧面板用于切换后台数据状态，切换后重新点击「资金未到账」即可看到对应分支：

| 场景数据状态 | 命中节点 | 结果形态 |
|---|---|---|
| P0·风控止出 | 风控状态 | 不可自助 → 转人工；阻断 P2/P3 |
| P0·风控调单 | 风控状态 | 可自助 → 调单详情；阻断后续 |
| P1·合同未签约 | 合同状态 | 可自助 → 签约页；阻断后续 |
| P1·资质过期 / 受益人 | 资质状态 | 可自助 → 资质/受益人页；阻断后续 |
| P0+P1 多异常 | 风控/合同/资质组合 | 高优先级异常同时展示，P2/P3 未执行 |
| P2·未开自动提现 | 结算配置 | 可自助 → 结算设置（P0/P1 正常后才诊断） |
| P2·卡异常 / 银行通道 | 最新出款批次 | 可自助改卡 / 不可自助转人工 |
| P3·分账失败 / 退款 | 分账、退款 | 转人工或安抚进度说明 |
| P2+P3 多异常 | 结算/出款/分账/退款组合 | 全部展示，均可处理 |
| 阻断演示 | 风控 +（配置了出款异常） | 出款项标记未执行 |
| 未发现异常 | — | 绿色对勾 + 安抚 + 联系客服 |
| 诊断超时（>5 秒） | 低优先级查询 | 「网络繁忙，是否转人工？」 |

公众号侧另可切换微信用户绑定状态：**未绑定/游客**（受限首页 + 图文绑定引导 + 商户号与验证码绑定）、**已绑定·单个盛意旺商户**（完整链路）、**已绑定·多个商户号**（默认上次商户，可切换，列表区分盛意旺 / 线下收单）、**已绑定·仅线下商户**（提示暂未开通并 3 秒后自动转人工）。

## 绑定方式（公众号）

1. 输入**完整商户号（6-8 位数字）**，系统实时校验格式与商户是否存在，并带出该商户的**预留手机号**（脱敏）。
2. 点击「获取验证码」下发短信（60 秒重发倒计时），输入 6 位验证码。
3. 校验通过后，服务端保存「微信 OpenID ↔ 商户号」关联关系（演示用 `localStorage` 模拟服务端，见 `mock.js` 的 `bindStore`），并记录 `lastMchId`。
4. 一个微信可绑定多个商户号：再次进入绑定页可追加绑定；进入助手时默认对**上一次查询诊断的商户号**发起排查，蓝色头图**右上角「切换商户」**可切换，列表中标注每个商户属于**盛意旺**还是**线下收单**；切到线下商户会走「暂未开通自助服务 → 自动转人工」。

演示控制台右上「当前识别结果」实时显示服务端里的绑定关系（OpenID、已绑定商户列表、上次使用商户、绑定时间）。

## 人工客服接入与诊断报告传递

### 客服地址

「人工客服」与「其他问题」入口现在直接跳转真实客服会话，两端使用不同 `codeKey` 区分接入渠道，在 `Assistant.init({ agentUrl })` 中配置：

| 场景 | 配置位置 | 地址 |
|---|---|---|
| 公众号 | `assets/js/wechat.js` | `https://chat.keqihui.com/any800/echatManager.do?companyPk=2c908e0f63b5e1e60163b5e5b7940001&codeKey=33` |
| 盛意旺 App | `assets/js/app.js` | `https://chat.keqihui.com/any800/echatManager.do?companyPk=2c908e0f63b5e1e60163b5e5b7940001&codeKey=28` |

用户主动点击转人工时立即打开客服窗口；线下商户倒计时自动转接时不自动弹窗（会被浏览器拦截），改为展示按钮由用户点击。

### 诊断报告独立链接

转人工时生成独立报告短链（GitHub Pages），仅携带诊断流水号：

`https://zanghuaqian.github.io/merchant-self-service/report.html?t=diag_xxxxxxxx`

（若远程备份成功会附加 `&r=`，便于他人跨设备打开；有效期 2 小时。）

- 报告 ID 与令牌均为随机值，**不可枚举**；有效期 2 小时，过期或令牌不符直接拒绝访问
- 报告内容按脱敏规则展示（账户名、卡号、证件号均打码），不含完整卡号与证件信息
- 演示环境用 `localStorage` 模拟服务端存储（`mock.js` 的 `reportStore`），真实实现需落库并由服务端签发令牌，同时记录客服访问审计日志

### 官方接口：`hjUserData`（客企汇《用户信息接口 V1.1》）

客企汇提供的用户信息接口要求：App/H5 把会员信息赋给 `hjUserData`，拼接到对话接入地址后。字段顺序与编码规则：

```
姓名|性别|固定电话|手机|邮箱|地址|公司名称|用户区域|QQ|会员ID|会员类型|扩展信息
```

- 每项单独 UTF-8 `urlencode`，再用 `|` 拼接
- 性别：`0` 保密 / `1` 男 / `2` 女
- 会员类型：`1` 普通会员 / `2` 代理商
- 无值则留空

本演示的字段映射：

| 接口字段 | 写入内容 |
|---|---|
| 姓名 / 公司名称 | 商户名称 |
| 地址 | 诊断结论摘要 |
| 扩展信息 | 诊断报告链接（仅 URL） |
| 手机 | 商户预留手机（脱敏） |
| 会员ID | **商户号**（客服识别身份的关键） |
| 会员类型 | `1`（普通会员） |

**结论：可以通过该接口传递商户信息；完整诊断报告不适合整段塞进字段，应放独立报告页链接，短链写入扩展信息字段。**

- ✅ 适合：商户号、商户名、手机、诊断结论摘要、报告链接
- ❌ 不适合：完整排查明细、结算卡明细、过长文本（客服工作台通常只展示短字段）

因此采用「`hjUserData` 传身份 + 扩展信息带报告链接 + 剪贴板兜底」：

| 层级 | 做法 | 状态 |
|---|---|---|
| ① 官方 `hjUserData` | 会员ID=商户号，地址=诊断结论，扩展信息=报告链接 | **已接入（待客服端确认展示）** |
| ② 独立报告页 | 短链 `report.html?t=诊断流水号`（GitHub Pages），2 小时有效 | **已可用** |
| ③ 剪贴板兜底 | 跳转前复制「商户号+结论+报告链接」，商户粘贴发送 | **已可用** |

### 实测与待确认

1. 此前用一洽体系的 `visEvt`/`myData` 实测：参数可不被 WAF 拦截，但会话内未出现图文消息；且 `myData` 内双重编码完整 URL 会被拦截。现已改为官方 `hjUserData`。
2. 上线前请向客企汇确认：客服工作台是否展示 `hjUserData` 全部 12 段、扩展信息字段长度上限、其中链接是否可点击、报告页域名是否需加入白名单。

### 其他可选方案（供对比）

- **工作台内嵌业务页**：客服接起会话即同屏 iframe 打开报告，体验最好，需客服后台配置业务页与免登。
- **服务端建工单**：风控/分账等必须跟进的结论，转人工时直接建工单并写入报告链接。
- **按商户号反查**：另做内部查询页，客服问商户号即可查看最近诊断，零对接成本但多一轮问答。

## 结算信息与结算规则

助手首页的「结算信息与结算规则」卡片、诊断报告页的折叠区，以及独立的结算信息页均展示当前商户的：

| 分组 | 字段 |
|---|---|
| 结算信息 | 结算卡类型（对公/对私）、结算卡账户名（脱敏）、结算卡号（脱敏）、归属银行 |
| 结算规则 | 结算周期（T+0/T+1）、日切时间、是否自动提现、预留金额、出款服务类型（随心提/安心提/交班提） |

结算数据与诊断场景联动：切到「未开自动提现」时自动提现显示为未开启并提示；切到「卡异常」时结算卡标记异常；切到「批次出款失败」时提示渠道/银行侧失败需人工核实；切到「风控冻结」时提示出款已暂停；切到「合同未签约」时提示电子合同未签暂停出款；切到「风控调单」时提示存在未处理调单暂缓出款，避免演示中结论与结算信息互相矛盾。

### 风控分支说明

风控节点会区分三类结论：

1. **风控冻结（不可自助）**：账户止出/冻结，解决方案为转人工。
2. **合同未签约（可自助）**：电子合同未完成签署时，主按钮为「去签约合同」，跳转签约页 `https://sass.shengpay.com/esign/ca/8SqKW499T0XMv2740994`（App / 公众号均内嵌打开）；签署完成后回到诊断报告，退出报告时收集反馈。
3. **风控调单（可自助）**：风控系统存在未处理调单记录时，主按钮为「去处理调单」，跳转调单详情页补充交易凭证；提交后回到诊断报告。真实环境中可将 `SOLUTIONS.risk_order.url` 配置为业务侧调单详情 H5 地址，演示会改为内嵌该页。

控制台底部实时输出埋点日志，对应 PRD 第 6 节：助手入口点击、资金未到账点击、诊断完成、**退出诊断报告反馈**（商户号 / 流水号 / 报告链接 / 已解决|未解决）、转人工、转人工携带快照等。
